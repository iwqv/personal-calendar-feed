# 个人 Apple 日历订阅源 · 2026

唯一订阅地址：[2026 个人日历](https://iwqv.github.io/personal-calendar-feed/calendar.ics)。在 Apple 日历的“添加订阅日历”中粘贴这个地址；可自行设置日历名称、颜色和显示状态。订阅内容只读，修改日程类别需编辑仓库配置并重新生成。原有两个分类链接保留给已订阅用户。

这是按截图中的**功能范围**制作的独立实现：不复制卖家的文案、品牌或黄历内容。日期范围只覆盖 2026 年，不自动推测 2027 年节假日。

## 文件

- `output/calendar.ics`：公开的唯一订阅源，合并下述两类日程
- `output/holiday.ics`：假期、调休、高速、抢票提醒；旧订阅兼容
- `output/festival.ics`：节日、纪念日、节气、礼物提醒
- `output/almanac.ics`：等待填入来源后生成的每日黄历；当前 **0 个事件**，无需订阅
- `docs/`：GitHub Pages 发布目录，含唯一订阅源、兼容旧订阅的文件和入口页；不要把空黄历或个人信息发布到这里
- `config.json`：可修改日期、文案、提醒开关和个人事件
- `almanac.csv`：自有或获授权的黄历数据入口，字段 `date,yi,ji,source`
- `build.mjs`：无第三方依赖的生成器，需要 Node.js 18 或更新版本

## 自己维护

修改 `config.json` 后运行：

```bash
node build.mjs
```

运行后 `docs/calendar.ics` 与两个旧分类源会一并更新。GitHub Pages 选择 `main` 分支的 `/docs` 文件夹；请在每次修改后重新提交 `docs/` 内的文件。

个人事件放在 `personal_events`，例如：

```json
{"title":"证件到期前检查", "date":"2026-12-01", "time":"09:00", "description":"检查证件有效期"}
```

黄历数据按天填入 `almanac.csv`，例如 `2026-09-18,祭祀,动土,已核实的数据来源`。CSV 内容不要包含半角逗号；没有来源的行会被拒绝。不同黄历体系的“宜忌”可能不同，生成器只转写你确认的数据。

## 订阅与自定义

订阅 [calendar.ics](https://iwqv.github.io/personal-calendar-feed/calendar.ics)；下载并导入 `.ics` 只会生成一次性副本。上传和更新时保留文件名及 URL 不变。Apple 刷新时间由客户端决定，不能保证即时推送。订阅日历可自定义名称、颜色、显示状态，但不能在 Apple 日历内对同一份订阅源逐项增删；需要在 `config.json` 中修改并重新生成公开文件。私人生日、证件等敏感事件不要放在公开静态地址，建议继续存在自己的私有日历中。

## 核对与维护

- 2026 放假及补班：[国务院办公厅通知](https://www.scio.gov.cn/zdgz/jj/202511/t20251110_938367.html)
- 24 节气日期：[香港天文台节气表](https://www.hko.gov.hk/sc/gts/astronomy/Solar_Term.htm)，北京时间与香港时间同为 UTC+8
- 高速免费通常适用春节、清明节、劳动节、国庆节的符合条件的小客车；具体车型、免费窗口及政策调整以交通运输部门公告为准
- 12306 预售期和各站起售时间可能调整。当前配置按“含乘车当日 15 天”计算，因此假期首日前 14 天显示参考提醒；购票前请在 12306 核对
- 每年新的放假安排公布后，须**更新配置和年份相关节气数据**再重新生成；生成器会拒绝未经核实的 2027 年

保留 `UID` 和 URL 相同，重新生成同一年度的事件可在刷新后更新；请不要把生成的 `.ics` 直接混同为可编辑的 iCloud 日历。
